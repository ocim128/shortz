# 2026-10-21

## Batch menu — accept bare file names / post ids

Problem: batch lines required a full absolute path; typing `2112680262353969521.mp4•Hook` failed at render with "File not found".

Change:
- New `src/main/batch-resolve.ts` — `BatchSourceResolver`. Resolution order: exact path (absolute or cwd-relative) → relative fragment under each root → name lookup in a lazily built index. Roots = `settings.downloads.dir` + `settings.output.dir`. Index walks once per run (cap 25k entries, depth 8, symlinks skipped), keys by lowercased name and stem, picks newest mtime when duplicated. Bare id (no extension) matches `<id>.<video ext>`.
- `src/main/batch.ts` — replaced `path.resolve` + stat with `resolver.resolve(item.path)`; removed `fsp` import.
- `src/shared/batch/parse.ts` — added `isBareStemLookup` (separator-free, whitespace-free, extension-less token) and `isResolvableSource`; parse now accepts bare ids but still rejects `C:\clips\noext` (paths must name a real file) and prose lines.
- UI: `batchIntro`, `batchInputPlaceholder`, new `batchLookupHint` in strings.ts; hint rendered in BatchScreen.
- Tests: `tests/unit/batch-resolve.test.ts` (9 cases), 3 new parse cases. 384 unit tests pass; typecheck + eslint clean.
